Tuning Jev questions with a loop

Jev answers typed questions in a fifth of a second for a fraction of a cent, so you can test a new wording on every labelled example you own in 20 seconds. That makes wording searchable. It also makes it easy to fool yourself. These are notes from one afternoon of doing it on legal citation checking.

§1 · The model

Jev reads your question literally

Jev (TypeSafe AI, jev-1.13.0) does not write text. You send a block of content called the state and one or more typed questions. It returns a probability for each answer. Three question types exist: Choice picks one labelled option, Score rates against ordered levels, and Noul answers yes or no.

All questions in a request are answered in parallel, so ten questions cost about the same as one. TypeSafe documents the weak spots plainly: it answers the words you wrote rather than the intent behind them, it loses accuracy as irrelevant state grows, and it should not be asked to count or compare dates.

Literal reading is why wording matters. It is also why a wording that works can be found by testing.

§3 · The loop

One round, six steps

The structure follows TypeSafe's own feature-discovery cookbook. Asking Jev something new costs a request per example. Recombining answers you already hold costs nothing. Spend the first carefully and the second freely.

    §4 · Guardrails

    Six rules that keep the score honest

    A loop that can try thirty wordings in ten minutes will find one that fits 100 examples by luck. Our first hand-picked threshold looked safe on its own data and let seven bad claims through on the next brief.

    Hold back whole briefs, and open them once.Four briefs were never shown to the loop or to the person writing questions. The final pick was scored on them a single time.
    Split by document, not by row.Claims from one brief share vocabulary. Set the threshold on the other briefs and test on the one left out.
    Declare which answer means “good” before looking.Each question file states its polarity. Nothing is flipped to fit the data.
    Questions state principles, never examples.An automatic check rejects case names, any seven-word run copied from a claim, and questions over 900 characters.
    Judge on a pessimistic number.Candidates are compared on the 20th percentile of claims cleared under resampling, so one lucky example cannot decide the round.
    Drop labels the labeller doubted.Eight ground-truth rows were marked “debatable” by their author. They were excluded from scoring and reported separately.
    Zero errors observed is a ceiling, not a zero.

    With no bad clears among n not-supported claims, the true rate can still be about 3 ÷ n at 95% confidence.

    §5 · Results

    A real gain, smaller than the tuning data promised

    Every claim that blocked the original wording had one shape: a compound proposition where the case supports the main point and not one clause. A label note read “supports the felony half, says nothing about misdemeanors.” Asking about the proposition as written was the fix.

    Most single-question gains did not carry over. The unseen briefs were simply easier for the original wording (.874 to .930).

    What the rewording bought is margin. With a threshold that leaves real headroom, the two wordings clear about the same number of claims. The original needs 0.90 to stay clean. The reworded question's worst not-supported claim sits near 0.30, so a threshold of 0.50 has room to be wrong. After three rounds the limit was no longer wording. It was the number of labelled not-supported examples.

    §6 · Try it

    A checklist for your own task

    1. Collect labelled examples grouped by source document. Aim for at least 50 of the class you must not get wrong.
    2. Set aside whole documents as a lockbox before writing anything.
    3. Send Jev only the text the question needs. Locating passages first separated the classes better and cut the state by 73%.
    4. Start with several plain, single-purpose questions in one request, and cache every response.
    5. Each round, read the worst failures with their reasons and write questions that name the general pattern.
    6. Search the combination rule over answers you already have. Keep it small: two to four signals.
    7. Replace the champion only on a pessimistic, cross-document win. Stop after two rounds without one.
    8. Open the lockbox once. Report the bound, not the zero. Then log every production run to grow the labelled pool.
